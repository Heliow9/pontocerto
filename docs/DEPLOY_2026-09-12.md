# Deploy Ponto Certo — correções offline e WhatsApp (2026-09-12)

## Escopo desta atualização

Esta atualização corrige os seguintes pontos:

- Bloqueio de marcações offline duplicadas do mesmo tipo na mesma jornada/dia.
- Defesa adicional no servidor contra duplicação semântica, além da idempotência por `requestKey`.
- Modo offline exibido somente quando não há conectividade com a internet.
- Fluxo de câmera visível no ponto offline, com prévia da selfie e opções **Aprovar** e **Refazer foto** antes de salvar a marcação.
- Tratamento de conflito HTTP 409 na sincronização offline, evitando tentativas infinitas para uma marcação rejeitada definitivamente.
- Reconexão do WhatsApp após leitura do QR e `restartRequired` do Baileys.
- Proteção contra corrida de estado em que um QR antigo poderia sobrescrever o estado `CONNECTED`.
- Persistência de credenciais antes de recriar o socket WhatsApp.
- Estados explícitos `RECONNECTING` e `LOGGED_OUT`.
- Botão **Desconectar WhatsApp** desabilitado quando a sessão está desconectada ou encerrada.
- Preservação dos alertas de ponto 5 minutos antes da batida.

## Pré-requisitos

- Node.js 22.13 ou superior.
- Repositório já clonado no servidor.
- `.env` existente e válido.
- PM2 com o processo `ponto-certo-api` configurado.
- Nginx já atendendo `hubpontocerto.duckdns.org`.

## Descobrir a pasta correta do projeto

Se não lembrar onde o projeto está no servidor:

```bash
pm2 describe ponto-certo-api
```

Procure o campo `exec cwd` e entre nessa pasta.

## Deploy após o merge no GitHub

```bash
cd /CAMINHO/DO/REPOSITORIO

git checkout main
git pull --ff-only origin main

bash scripts/deploy-server.sh
```

O script de deploy do próprio projeto:

- valida a versão do Node;
- executa `npm ci --include=dev`;
- gera o build da API;
- gera o build do painel web;
- gera o build do PWA/mobile web;
- executa as migrations pendentes;
- executa os setups de push e WhatsApp;
- reinicia `ponto-certo-api` com PM2;
- identifica a raiz real do PWA configurada no Nginx para `hubpontocerto.duckdns.org`;
- cria backup dos arquivos publicados;
- publica painel e PWA;
- valida o Nginx e recarrega o serviço.

## Testes funcionais recomendados após o deploy

1. Com internet ativa, confirmar que o modo offline não aparece.
2. Desligar Wi-Fi e dados móveis e confirmar que o botão muda para **Registrar ponto offline**.
3. Abrir o ponto offline, tirar uma selfie, conferir a prévia, tocar em **Refazer foto** e capturar novamente.
4. Aprovar a foto e confirmar que a marcação fica salva localmente.
5. Tentar registrar o mesmo tipo novamente no mesmo dia/jornada e confirmar o bloqueio.
6. Registrar o próximo tipo válido (ex.: saída para intervalo) e confirmar que é aceito.
7. Reativar a internet e confirmar a sincronização automática sem duplicar a marcação.
8. No painel da empresa, confirmar que **Desconectar WhatsApp** está desabilitado quando o estado for `DISCONNECTED` ou `LOGGED_OUT`.
9. Gerar um QR, escanear no celular e aguardar até o painel exibir `CONNECTED` sem ficar preso em “Conectando”.
10. Reiniciar a API com `pm2 restart ponto-certo-api --update-env` e confirmar que a sessão WhatsApp é restaurada.
11. Confirmar que os alertas de 5 minutos antes das batidas continuam funcionando.

## Observação sobre banco de dados

Estas correções não criam uma nova migration específica. O deploy mantém `npm run db:migrate --workspace apps/api` porque o script padrão do projeto já executa migrations pendentes de versões anteriores com segurança.
